## Diagnosing "recurring" issues

A symptom is not recurring until the setup that produces it is confirmed
identical to the prior instance — same inputs, versions, configuration,
environment, and code path. Contexts change often; a past instance under a
different setup is **inapplicable**, not confirming or contradicting evidence.

- Name the exact context in any finding: which version, which config, which
  environment, which inputs. A bare symptom ("it fails", "it's slow") is
  meaningless without it.
- Before invoking a past instance as precedent, re-verify the current setup
  matches it. Pattern-matching across a changed setup manufactures false
  patterns and sends you chasing the wrong layer.
- Devil is in the details: weight the specific setup over the surface-similar
  symptom.
